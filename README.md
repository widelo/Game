# CS 462 Game

A first-person hospital horror roguelike. Every run generates a new hospital floor: rooms, corridors,
furniture, lights, three keys to find, and one way out — the room you started in.

## Opening the project

- **Unity 6000.6.2f1** (exact version; open it from Unity Hub so it does not silently upgrade the project).
- Render pipeline: **URP 17.6, Forward+**. The active pipeline asset is `Assets/Settings/PC_RPAsset.asset`.
- **Active Input Handling = Both.** Teammates' player uses the Starter Assets Input System controller
  (`Assets/Starter Assets/`); the level-generation test scene uses our own legacy-input
  `Game.Player.FirstPersonController`. Both work because the setting is Both — do not change it to one or the other.
- First open takes a while (shader + asset import). That is normal.

## Scenes

| Scene | Whose | What it is |
|---|---|---|
| `Assets/Scenes/SampleScene.unity` | the team's | The shared playground. **Do not modify from the level-gen branch.** |
| `Assets/Scenes/Main.unity` | level generation | The generator test scene: a `LevelBuilder`, a player, a debug HUD. **Generated by code** — see below. |

`Main.unity` is not hand-authored. It is produced by `Game.Editor.SceneBootstrap.CreateMainScene`, so if you
change generation defaults, regenerate the scene rather than editing it in the inspector — otherwise the stale
serialized values in the scene file win.

## Controls (Main.unity)

| Input | Action |
|---|---|
| `WASD` / mouse | move / look |
| `Shift` | sprint |
| `Space` | jump |
| `Ctrl` or `C` | crouch (sprint + crouch = slide) |
| `Esc` | release / recapture the mouse cursor |
| `R` | rebuild the level with the same seed |
| `N` / `P` | next / previous seed |
| `L` | flat-light everything (see geometry through the murk) |
| `F1` | toggle the HUD |
| `Tab` | overhead map view — `WASD` pans, scroll zooms, `Home` refits |

The HUD shows the seed, room/corridor/prop/light counts, the spawn and key rooms, and — for the room you are
standing in — its archetype, its **template name** and its **door count**.

## The CS462 menu

| Menu item | What it does |
|---|---|
| `CS462/Create Main Scene` | Regenerates `Assets/Scenes/Main.unity`, applies the URP light budget, creates `Assets/LevelGen/` assets, appends Main to Build Settings. |
| `CS462/Rebuild Level In Scene` | Rebuilds the level in the open scene in edit mode (no Play needed). |
| `CS462/Create Default Level Gen Assets` | Creates/repairs `Assets/LevelGen/DefaultLevelGenProfile.asset` and the sample room templates. |
| `CS462/Apply URP Settings` | Sets the URP asset's additional-light shadows / per-pixel mode / light count. |
| `CS462/Headless Verify (20 seeds)` | Builds 20 seeds and checks layout, content, NavMesh reachability and template usage. |

The `LevelBuilder` inspector also has **Build (seed)**, **Build random**, **Verify 20 seeds**, and — when the
profile slot is empty — **Create/assign default profile**.

## Running the tests

**In the editor:** `Window > General > Test Runner`, EditMode tab, **Run All**. These are pure-C# tests over
`LevelGen.Core` (determinism, validator over many seeds, room counts, shapes, templates) and need no scene.

**Headless, from a shell** (paths are for this machine; from WSL, prefix with `wsl -e bash -lc` as needed):

```sh
UNITY="/mnt/c/Program Files/Unity/Hub/Editor/6000.6.2f1/Editor/Unity.exe"
PROJ='C:\Users\schmi\projs\Game'

# 1. compile check only
"$UNITY" -batchmode -nographics -quit -projectPath "$PROJ" -logFile "$PROJ\Logs\compile.log"

# 2. edit-mode unit tests
"$UNITY" -batchmode -nographics -projectPath "$PROJ" \
         -runTests -testPlatform EditMode \
         -testResults "$PROJ\Logs\results.xml" -logFile "$PROJ\Logs\tests.log"

# 3. regenerate Main.unity (also writes Assets/LevelGen/* and the URP settings)
"$UNITY" -batchmode -nographics -quit -projectPath "$PROJ" \
         -executeMethod Game.Editor.SceneBootstrap.CreateMainScene -logFile "$PROJ\Logs\scene.log"

# 4. the real smoke test: 20 seeds, built, validated, NavMesh-path-checked
"$UNITY" -batchmode -nographics -quit -projectPath "$PROJ" \
         -executeMethod Game.Editor.HeadlessVerify.BuildLevels -logFile "$PROJ\Logs\verify.log"
```

Only one Unity instance may have the project open at a time, so close the editor before running these.
Each command exits non-zero on failure; the detail is in the log file.

## Docs

- `docs/HOW-GENERATION-WORKS.md` — **start here if you have not read the code.** Plain-language walkthrough
  plus a FAQ (yes, we can generate a floor under your prefab room; yes, the spawn room can have one entrance).

## Branch workflow

Work on a feature branch and open a **pull request into `main`** — nothing is pushed straight to `main`.
Level-generation work lives on `carson/level-generation` and lands through pull requests into `main`.
